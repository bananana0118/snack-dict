# Snack Dict Design Guide

## 역할

이 문서는 Snack Dict의 시각적 의사결정 기준을 정리한다.
폴더 구조, React 작성법, Storybook 작성법, CSS 책임 분리는 기존 `agent-docs/*` 문서를 따른다.

## 브랜드 성격

Snack Dict는 국내 과자를 리뷰하고 분류해 보여주는 신문형 과자 리뷰 서비스다.

디자인은 신문 상단의 큰 제목 영역, 날짜, 구분선, 섹션 제목, 카테고리 탭처럼
신문 지면에서 볼 수 있는 구조를 바탕으로 한다.

과자라는 소재의 재미는 상품 이미지와 맛 태그 색상으로 드러내되,
전체 UI는 정돈된 흑백 지면처럼 정보가 또렷하게 읽히는 방향을 우선한다.

핵심 키워드:

- 국내 과자 리뷰
- 신문형 레이아웃
- 정돈된 흑백 지면
- 분류와 비교
- 맛 태그
- 리뷰 기반 탐색
- 절제된 위트

## 디자인 원칙

- 화면은 신문 지면처럼 명확한 구획과 위계를 가진다.
- 섹션은 굵은 선, 얇은 선, 제목, 날짜, 카테고리 탭으로 구분한다.
- 장식적인 카드 UI보다 선, 간격, 타이포그래피로 구조를 만든다.
- 정보는 검색, 신상품, 전체 과자, 등록 기준처럼 명확한 섹션 단위로 나눈다.
- 과자 분류와 맛 정보는 태그 색상으로 빠르게 구분한다.
- 리뷰 서비스이므로 사용자가 과자를 찾고 비교하고 판단하기 쉬운 구조를 우선한다.
- Figma에 없는 시각 효과를 임의로 추가하지 않는다.

## 색상 원칙

색상값의 기준은 `src/shared/styles/tokens.css`이다.
이 문서에서는 색상값을 다시 정의하지 않고 사용 맥락만 설명한다.

- `gray` 계열은 신문형 레이아웃의 제목, 본문, 구분선, 보조 배경에 사용한다.
- `category` 계열은 과자 분류 태그에만 사용한다.
- `taste` 계열은 맛 태그에만 사용한다.
- `system` 계열은 에러, 일반 상태 같은 시스템 피드백에만 사용한다.
- 강한 색상은 정보 분류를 위한 태그에 제한적으로 사용하고, 지면 전체를 장식하는 용도로 사용하지 않는다.
- 새 색상이 필요하면 컴포넌트에 직접 하드코딩하지 않고 토큰 추가 여부를 먼저 검토한다.

## 타이포그래피 원칙

Snack Dict의 타이포그래피 값은 `src/shared/styles/typography.css`를 기준으로 한다.

디자인 가이드에서는 다음 역할 구분만 정의한다.

- 신문 상단 제목/큰 제목: 서비스명, 주요 화면 제목처럼 신문 지면의 큰 제목 역할
- 섹션 제목: 검색, 신상품, 전체 과자, 등록 기준처럼 지면을 나누는 제목 역할
- 본문: 설명문, 리뷰 요약, 안내 문구
- 보조 정보: 날짜, 개수, 정렬, 푸터, 캡션
- 태그 텍스트: 맛/분류 정보를 빠르게 구분하는 짧은 라벨

구체적인 size, line-height, letter-spacing, font-weight는 `--snack-dict-text-*`와 `--snack-dict-font-weight-*` 토큰을 사용한다.
컴포넌트 CSS에 Figma 값을 임의로 하드코딩하지 않는다.

## 스페이싱 원칙

스페이싱 값은 Figma와 기존 토큰을 우선 기준으로 하며, 이 문서는 반복적으로 쓰이는 간격의 사용 맥락만 설명한다.

- 신문 지면처럼 여백과 구분선으로 섹션을 나눈다.
- 작은 요소 간 간격은 4px 또는 8px 단위를 우선 사용한다.
- 섹션 내부 여백은 16px을 기본 기준으로 본다.
- 큰 섹션 간 간격은 32px을 기본 기준으로 본다.
- Figma와 다르게 임의의 미세 간격을 추가하지 않는다.

## 쓰지 말 것

- 귀여운 간식 앱처럼 보이게 하는 과한 radius, shadow, gradient
- 임의 hex, rgb, hsl 색상 추가
- Figma에 없는 variant 추가
- Pretendard 외 폰트 사용
- 장식용 일러스트나 이모지 남발
- 리뷰 서비스 범위를 넘어서는 과장된 글로벌 문구
- 화면에서 shared UI의 색상, border, shadow를 다시 덮어쓰기
